Lifecycle & Best Practices

DOM Injection Timing

AnimeCursor v2 does not inject any DOM elements (except the optional debug overlay), so there are no constraints on when you create the instance. However, to ensure images are preloaded early, it's recommended to initialize AnimeCursor as early as possible, preferably before the DOM finishes loading.

If you add new content dynamically (e.g., via AJAX, Markdown rendering, SPA route changes), call refresh() after the new content is inserted. This will regenerate the CSS rules and apply cursor definitions to the new elements.

❌ Incorrect example:

new AnimeCursor();
fetchMarkdown(); // but no refresh() after insertion

✅ Correct examples:

fetchMarkdown().then(() => {
    new AnimeCursor(); // OK, but better to initialize early and refresh
});

Or

const cursor = new AnimeCursor();
fetchMarkdown().then(() => cursor.refresh());

Usage with Markdown / SPA

  • Call refresh() after Markdown rendering is complete.

  • Call refresh() after SPA route changes.

  • Avoid creating a new instance on every update – reuse the existing one and call refresh().

Performance Tips

  • AnimeCursor v2 uses only CSS and no continuous JavaScript listeners (except debug mode). Performance is excellent out‑of‑the‑box.

  • If you have many cursor types, the CSS rules will still be lightweight; they are generated once and applied by the browser.

  • Use excludeSelectors to prevent overriding native text cursors on input fields – this improves usability.
