Debugging & Troubleshooting

Debug Mode

Enable debug mode

new AnimeCursor({
    debug: true,
    cursors: {...}
});

Debug mode displays:

  • Current mouse coordinates

  • Current cursor type (or "native" if no custom cursor matches)

Debug mode is useful for calibrating hotspot offsets, testing cursor switching, and verifying that your frames are loading correctly.

Common Issues

Element's own animation overrides the cursor animation

  • Enable the combineAnimations: true option and add a data-ac-animation attribute to the element, containing your custom animation definition. AnimeCursor will then combine both animations.

  • Example: 

    <button data-ac-animation="mySpin 2s infinite">Click Me</button>

    with combineAnimations: true.

Cursor not showing / No change

  • Check the image path – ensure the first frame exists and the naming pattern is correct.

  • If using animated cursors, verify frames and duration are both set and valid (numbers or arrays). Check the console for warnings.

  • Check that tags match the intended elements, or that data-cursor is correctly set on elements.

  • Did you call refresh() after dynamic DOM changes?

  • Was destroy() called inadvertently?

Animation doesn't play / plays incorrectly

  • Ensure frames and duration are both set and valid.

  • For variable‑speed animations, make sure both are arrays of equal length and contain positive numbers.

  • All frame images must exist at the automatically generated URLs. Check the network tab to see if 404 errors occur.

The cursor briefly disappears when switching to a new cursor for the first time

  • Images may not be fully loaded yet. Preload tags are inserted early, but large images might still cause a short delay. Consider compressing images.

  • Make sure AnimeCursor is initialized before the DOM finishes loading (not inside a DOMContentLoaded callback).

[Known Issue] When testing with live server and Firefox, the default cursor may occasionally fail to display even with correct configuration and no console errors. However, this issue does not occur when viewing the actually deployed page with Firefox. The root cause is currently unknown.
